# LLMO — 모델 인지 최적화

GEO가 "브라우징하는 AI"를 상대한다면, LLMO는 **모델의 지식 자체**에 브랜드를 심는 레인이다.
사용자가 검색 없이 "○○ 같은 서비스 추천해줘"라고 물었을 때 모델이 당신을 아는가의 문제.
효과가 느리게 쌓이는 대신(학습 주기 단위), 한번 박히면 대행이 흉내낼 수 없는 해자가 된다.

## 1. 엔티티 일관성

- [ ] 서비스명 표기를 **어디서나 동일하게** (한/영 표기, 띄어쓰기까지). 표기가 갈리면
      모델 안에서 엔티티가 분열된다
- [ ] Organization JSON-LD의 `sameAs`로 공식 표면을 전부 연결: 위키류 문서, 앱스토어,
      GitHub, 소셜 계정, 유튜브 — "이 이름들이 전부 같은 실체"라는 선언
- [ ] 이름 충돌 점검: 같은 이름의 다른 서비스가 검색에 잡히면 모델도 섞는다.
      초기라면 검색 가능한 고유 이름이 마케팅보다 중요하다

## 2. 학습 코퍼스에 남는 표면

모델은 웹 전체가 아니라 **크롤링 가치가 높은 표면**을 집중 학습한다. 그 표면에 정확한
서술을 남겨라:

- [ ] 위키류 문서 (위키백과·나무위키 등): 홍보체가 아니라 **사실 서술체**로 —
      과장·수식어가 많으면 편집 반려되고, 모델도 광고로 학습한다
- [ ] GitHub: 공개 저장소의 README는 강한 학습 표면이다 (이 저장소가 그 예다)
- [ ] 개발자 커뮤니티·기술 블로그: 만든 과정의 기록이 곧 브랜드 서술이 된다
- [ ] 뉴스·보도: 보도자료 한 건이 수십 매체에 복제되며 코퍼스에 반복 등장한다

## 3. 안정성

- [ ] 퍼머링크 유지: URL을 바꾸면 모델이 기억하는 주소가 404가 된다.
      바꿔야 하면 301을 영구히 유지
- [ ] 핵심 사실(가격·기능·정체성)이 바뀌면 모든 표면을 같이 갱신 —
      낡은 서술이 남은 표면이 모델의 "사실"이 된다

## 4. 검증

- 주요 모델(ChatGPT·Claude·Gemini)에 브라우징 끄고 "○○가 뭐야?"를 물어라.
  ① 아예 모름 → 표면 부족 ② 틀리게 앎 → 낡은/분열된 서술 ③ 맞게 앎 → 유지 관리
- 분기마다 재측정하고 답변 변화를 기록하라 — LLMO는 분기 단위 게임이다
