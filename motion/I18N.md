# Scene translation — brief (English first)

The film's 21 scenes (`motion/pilot/<scene>.html`) are played live in the browser at https://one-scroll-bible.com/film/.
We are making every scene playable in other languages. **Korean stays the source**: each scene still writes its
on-screen text in Korean, and a language file maps each exact Korean string to its translation.

## How it works (already built — read `motion/pilot/lib.js`, top "languages" block)
- `?lang=en` → `lib.js` loads `pilot/i18n/en.json` before `init`, then `Pilot.text()` draws `Pilot.tr(s)` instead of `s`,
  shrinking the font if a translated line is wider than the frame (or `o.maxW`). With no `lang` (Korean) nothing changes.
- `Pilot.tr(koreanString)` → translation (or the Korean if missing). `Pilot.chars(s)` → user-perceived characters
  (grapheme clusters) for typewriter/char-by-char effects. `Pilot.lang`, `Pilot.dir` ('ltr'|'rtl') are available.
- Translations live per scene in `motion/pilot/i18n/en/<scene>.json` (`{ "한국어 원문": "English" }`, the key is the
  **exact** Korean string as drawn, including `\n`, quotes and spacing). `node motion/i18n-merge.mjs en` merges them into
  `pilot/i18n/en.json`. Never hand-edit `en.json`; only your own scenes' files in `i18n/en/`.
- Worked example: `cross.html` needed no code change; see `motion/pilot/i18n/en/cross.json`.

## Your job per scene
1. **Route every on-screen string through `Pilot.tr`.** `node motion/i18n-scan.mjs ko <scene>` lists `ids` (already
   translatable) and `direct` (Hangul drawn to the canvas without going through `Pilot.tr` — your own fillText helpers,
   typewriters, char-by-char layouts, labels). Fix the scene so `direct` becomes empty:
   - Translate the WHOLE string first, then animate/slice the result: `const s = Pilot.tr('…'); const ch = Pilot.chars(s); …slice(0, k).join('')`.
   - Don't hard-code per-character positions/widths that only work for Korean; measure the translated text.
   - Generated text (counters like `343년`, numbers): translate a template with a placeholder, e.g.
     `Pilot.tr('{n}년').replace('{n}', n)`, and put `"{n}년": "{n} years"` in the language file.
   - Korean-specific visuals must become language-driven but look the same in Korean: e.g. a gilded initial letter =
     first grapheme of the translated verse; a giant decorative glyph = its own translatable key.
   - **Korean output must stay pixel-identical** (or as near as possible). Before editing, render a few Korean stills;
     after, render the same and compare (`ffmpeg -i a.png -i b.png -filter_complex "blend=all_mode=difference,signalstats" -f null -`
     or just look). Korean is the shipped film — do not change its look, timing or wording.
2. **Write `motion/pilot/i18n/en/<scene>.json`** with an entry for every string in `ids` (re-run the ko scan after step 1).
   - **Scripture: ESV, verbatim, never paraphrased or typed from memory.** Fetch it:
     `node .claude/skills/add-language/lib/fetch-verse.mjs 59 LUK.23.44,ISA.53.5` (USFM book codes). Show the contiguous
     ESV fragment that matches what the Korean shows (use `…` for a gap inside one verse, as the Korean does). Poetry lines
     can come back joined without a space (`transgressions;he`) — restore the space, nothing else. Versification follows the
     ESV. Cite as `Luke 23:44 (ESV)` (full English book name).
   - **Site prose** (lines the scene quotes from the site, e.g. epoch lines, FAQ, the prayer): use the site's English
     **exactly** from `i18n/en.json` (the English pack of index.html). Find the Korean in `index.html`, find the matching
     English in the pack (same section/key). Don't retranslate it.
   - **Scene-only labels** (chapter labels, captions like `열 가지 재앙`, map names, plate labels): natural, short English,
     faithful to the Korean meaning and to the evangelical/Reformed perspective of the site. Chapter label format:
     `12  ·  The Cross` (keep the scene's spacing). Use the English site's terms (epoch titles: Creation, The Fall,
     The Patriarchs, …, The Silent Years, Jesus Comes, The Church Begins, Restoration).
   - Line breaks: put `\n` where an English line should break; keep ≤ 2 lines on screen; portrait variants (Korean keys
     that differ only by `\n`) get their own English line breaks.
3. **Check:** `node motion/i18n-merge.mjs en && node motion/i18n-scan.mjs en <scene>` must print `complete` with no leaks.
   Then render English stills in both orientations and LOOK at them:
   `node motion/render.mjs h --page pilot/<scene>.html --lang en --stills 3,10,…` (and `v`) → `motion/out/still-<scene>-en-<h|v>-<t>.png`.
   Fix overflow, overlap with subjects, awkward breaks, unreadable sizes. Re-check a couple of Korean stills too.

## Rules
- Don't render videos (no `render.mjs` without `--stills`). Don't commit. Don't touch `lib.js`, `render.mjs`, other people's
  scenes, `film/`, or `index.html`. If you need a `lib.js` change, describe it in your report instead.
- The scratchpad is shared — keep your temp files in your own subfolder.
- Report briefly: per scene what code changed, strings count, anything uncertain (e.g. a fragment choice, a label wording).
