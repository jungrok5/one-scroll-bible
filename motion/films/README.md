# 새 영상(필름 시리즈) — 제작 전략과 기준

> 「한눈에 보는 성경 이야기」(21장면, 14분) 다음부터 만드는 영상의 기준이다. 첫 영상을 만들고 퍼뜨리며 겪은 일을 바탕으로
> 2026-10-29~30에 관리자와 정한 것들을 모았다. 첫 영상(21장면)의 제작·업로드 절차는 [../README.md](../README.md)에 있다.
> 새 영상을 시작하거나 방향을 바꿀 때 이 문서부터 읽고, 정한 것이 바뀌면 여기를 고친다.

## 1. 무엇을 위해 만드나

- **주 대상: 성경을 잘 모르는 크리스천.** 목표는 성경 내용을 전하고, 성경과 가까워지게 하고, **직접 성경을 펴서 읽게** 하는 것이다(2026-10-30 결정).
  - 비신자 반응은 참고하되 **우선순위는 맨 뒤**다. 여호와·인자 같은 성경 용어는 바깥 사람에게 맞춰 순화하지 않는다.
  - 성경 속 위치를 보여 준다(책·장, 구약→신약 연결). 끝 화면은 **읽기 안내**(영상에 나온 장)로 끝낸다.
- **감동과 전율, 영화 같은 느낌.** 정보를 많이 담는 것보다 **감정의 흐름 하나**가 중요하다. 연도·배경 역사는 설명란·고정 댓글·사이트로 넘긴다.
- **내용이 먼저다.** 3분 안에 넣으려고 서두르지 않는다. 담을 것이 많으면 줄이고, 남은 시간은 전율 장면과 숨 쉴 자리에 준다.

## 2. 형식

| 항목 | 기준 | 이유 |
|---|---|---|
| 길이 | **3:00 미만**(2:59까지) 한 편 | 유튜브 쇼츠·인스타 릴스 공통 상한이 3분. 파일 하나를 모든 플랫폼에 그대로 올린다 |
| 화면 | **세로가 기준**, 가로는 같은 코드에서 구도만 바꿔 뽑음 | 첫 영상은 가로 14분을 먼저 만들고 쇼츠로 쪼개느라 도입부 자르기·문장 경계·다음 편 댓글·21개 예약 등 운영 노동이 컸다 |
| 연재 | 한 편 완결 | "다음 편" 고정 댓글이 필요 없게 |
| 가로판 | 유튜브 일반 영상, 사이트 /film, 교회 스크린 | |
| 예고편 | 선택(전율 장면 15–30초, 1–2개) | 성과를 보고 정함 |

**세로 화면의 가려지는 곳**: 쇼츠·릴스는 아래쪽(채널명·제목·버튼)과 오른쪽(좋아요·댓글 버튼 열)을 덮는다.
자막과 핵심 그림은 실제 앱 화면을 겹친 모형으로 확인하고, 아래 약 25%와 오른쪽 가장자리를 피한다.

## 3. 원고와 글자

- **해설 원고 = 화면 글자.** 목소리로만 나오고 화면에 없는 문장은 만들지 않는다(소리를 못 듣는 사람, 무음 재생, 목소리 없는 언어판).
  - `script.json`: 줄마다 **id**(번역의 열쇠). `text` = 화면 글자, `voice` = 읽는 부분(반드시 `text` 안에 그대로 있어야 함), `voice: null` = 화면 전용.
  - `kind`: `narr`(해설) · `quote`(성경 원문) · `label`(화면 표기). `/` = 세로 화면 줄바꿈 자리.
  - 한국어 문장을 고쳐도 번역은 id로 이어진다(고친 줄은 번역을 다시 확인). 첫 영상은 한국어 문장 자체가 열쇠라 한 글자만 고쳐도 모든 언어에서 그 줄이 빠졌다.
- **성경 인용은 그 언어 공인 번역본 원문 그대로.** 한국어는 개역개정이다.
  - `node motion/films/check-quotes.mjs <폴더>`로 bskorea 원문과 글자 단위로 대조한다(WebFetch는 구절을 지어내므로 쓰지 않는다).
  - 장절 번호는 그 성경의 번호를 따른다(예: 독일어 말 4:6 = 3:24). 두 구절을 잇는 연출은 겹쳐 쓰기 대신 **위아래로 놓고 금빛 선으로 잇는다**(어느 언어 성경에서도 성립).
  - 외경(마카베오 등)은 성경으로 인용하지 않고, 역사 자료로 설명란에만 쓴다.
- **읽히는 글씨.**
  - 첫 영상과 같은 명조(Noto Serif KR 600)를 쓰되 크게 쓴다. 첫 영상 자막은 세로 72px, 이번 영상 초안은 42–54px라 폰에서 약했다.
  - 한 번에 한두 줄만 띄운다. 긴 구절은 조각마다 바꿔 띄우거나 핵심만 인용한다.
  - 읽는 시간은 **1.5초 + 글자당 0.12초** 이상을 준다. 글자는 그림 위에 얹지 않는다(어두운 띠·빈 자리).
- **유튜브**에는 화면 글자와 별도로 자막 파일(SRT)도 올린다(검색·자동 번역).

## 4. 다국어 — 언어를 세 단계로 (2026-10-29 확정)

| 단계 | 언어 | 만드는 것 |
|---|---|---|
| **A. 배포 언어** | 한국어(+ 영어) | 언어별 영상 파일 + AI 해설 + 모든 플랫폼 게시. 그 언어를 보는 사람이 있는 계정이 있는 언어만 |
| **B. 유튜브 언어** | 유튜브에서 반응이 확인된 언어 | 유튜브에만. 목소리 없이 화면 글자, 제목·설명은 그 언어로. 반응을 보고 늘리거나 줄임 |
| **C. 나머지 전부** | 사이트의 모든 언어 | **영상 파일 없이 사이트 /film에서만**(브라우저가 그 자리에서 각 언어로 그림 — 언어가 늘어도 파일·업로드·예약이 늘지 않음) |

- 소셜은 한국어·영어로 사람을 사이트로 데려오는 역할이고, 다국어는 사이트가 맡는다. 링크는 사이트로 보내고, 사이트가 브라우저 언어를 맞춘다.
- **목소리는 A단계에만.** 내용이 전부 화면에 있으므로 B·C는 글자로 충분하다(ElevenLabs 비용이 언어 수만큼 늘지 않음).
- 인스타·스레드는 한 게시물에서 언어별 자막을 바꿀 수 없다(영상 속 글자는 한 언어로 고정, 캡션 자동 번역 정도).
- 번역은 **한국어 원고를 확정한 뒤** 시작한다. 검수 기준은 사이트와 같다: 산문은 역번역 확인 + 원어민 검수를 통과한 언어만 공개, 아니면 미룬다.

- **한국어 외 모든 언어**: 유튜브 국제 채널 「Bible in One Scroll」(@bibleinonescroll) — 2026-10-26부터. 머리말은 `motion/youtube/global-move.mjs`.
- 업로드·예약·재생목록은 [../README.md](../README.md)의 "브라우저와 API 나눠 쓰기" 기준(업로드·관련 동영상·댓글 고정 = 스튜디오, 정보 채우기·예약·확인 = API, 하루 10,000점).

## 6. 사이트 /film 개편 (영상을 올릴 때 함께 — 2026-10-30 승인)

1. **/film/ = 영상 모음.** 맨 위에 최근 영상을 크게, 아래에 모든 영상 카드(포스터·제목·길이·가로/세로·볼 수 있는 언어).
2. **영상마다 자기 주소.** 예: `/film/story/`(14분 전체 이야기), `/film/silence/`(침묵의 400년). 공유·검색 노출·VideoObject를 영상별로.
3. **기존 링크는 그대로.** 이미 퍼진 `/film/?lang=..#cross` 같은 주소(유튜브 설명란·인스타)는 `/film/story/`의 같은 장면으로 자동 연결.
4. **재생기 하나.** 장면을 이어 붙인 영상과 한 파일짜리 영상을 같은 재생기로. 목록은 `films.json` 하나(새 영상 = 한 줄 추가).
5. 메인의 "14분 영상으로 보기" → "영상으로 보기".
6. GA 이벤트에 `film`(어느 영상인지)을 붙여 영상별로 비교.

main 배포는 관리자 허락을 받고 한다.

## 7. 만드는 방식 (코드)

- 한 파일짜리 캔버스 영상: `motion/films/<이름>/film.html` + `script.json` + 장면별 그림 모듈. 공용은 `../pilot/lib.js`, `lib-film.js`.
- **화풍은 첫 영상의 것을 다시 쓴다**(금박 필사본, 잉크 지도, 종이 오림, 스테인드글라스, 금빛 선). 글자는 그림 안에 그리지 않는다.
- 시간표: `SCENES`·`TEXT`는 이야기 시계로 적고, `EDIT` 표(영상 시간 ↔ 이야기 시계)로 전체 간격을 한곳에서 조정한다. 장면 사이는 0.7초 겹쳐 녹아드는 전환.
- 렌더: `node motion/render.mjs v|h --page films/<이름>/film.html [--stills a,b] [--workers 6]`. 검토용 720p와 2초 간격 밀착 시트로 글자 겹침을 확인한 뒤 보낸다.

## 8. 검토 순서

1. **시나리오·원고를 먼저 제안하고 컨펌**받은 뒤 그린다. 큰 연출 변경도 계획 → 컨펌 → 작업.
2. **관점 검수**(복음주의·개혁주의 구속사, 개역개정): 지적은 반영한다.
3. **시청자 리뷰**(성경 잘 모르는 크리스천 · 성경 잘 아는 신자 · 비신자): 고치지 않고 결과만 모아 보고, 관리자가 고를 것을 정한다. 1번 대상의 의견이 우선.
4. 관리자와 아내분이 720p 시안으로 본다. 가능하면 성경을 잘 모르는 가족에게도 보여 준다(목소리가 들어간 뒤).

## 9. 첫 영상과 「침묵의 400년」에서 배운 것

- **새로 넣은 것이 많을수록 급해지고 품질이 떨어졌다.** 장면을 더하기보다 덜고, 남은 장면을 공들인다.
- **전율 장면은 시간이 필요하다.** 글을 다 읽기 전에 밑줄이 지나가면 전율이 없다. 소리가 없어도 시각만으로 고급스러워야 한다.
- **왜 전율인지 화면이 말해 줘야 한다.** 성경을 모르면 "같은 말이 이어진다"의 의미를 모른다. 사람(세례 요한), 물건(손대지 아니한 돌)은 **이름과 뜻**을 화면에 준다.
- 낯선 상징(신상)은 무엇이고 어디서 읽는지 먼저 알린다("다니엘 2장 · 느부갓네살 왕의 꿈").
- 지도에 시대가 안 맞는 지명을 두지 않는다(페르시아 시대의 알렉산드리아).
- HUD(이름표·작은 그림·연도·메달)가 한꺼번에 많으면 산만하다. 이야기에 필요한 것만.
- 무언가 "하얀 언덕"처럼 정체를 알 수 없는 그림은 빼거나 바꾼다. 효과가 겹치거나(입자와 다음 장면) 깜빡이면 싸 보인다.
- 글씨 대비: 금빛 글씨가 양피지 위에서 빛나면 묻힌다 — 잉크는 진하게, 빛은 글자 뒤에.

## 10. 계속 만들지 — 이 한 편으로 판단

시험작(침묵의 400년)을 올리고 약 2주 뒤 숫자로 정한다. 기존 21편 쇼츠 지표(11/06 수집)와 비교한다.

- 볼 숫자: 평균 시청 비율, 공유·저장, utm 링크 유입, 사이트 기도문 완독(`prayer_complete`).
- 좋으면: "성경의 빈칸" 같은 시리즈(400년, 바벨론 포로 70년, 사도행전 이후 등). 같은 형식이 쌓이면 편마다 제작 시간이 준다.
- 못 미치면: 새 영상보다 기존 자산(사이트, 21편)을 각 언어로 퍼뜨리는 데 힘을 쓴다.

- **소리(14차, 2026-10-31)**: 해설 29줄(첫 영상 해설판과 같은 목소리·모델, 줄당 한 번) + 음악 9곡(줄 수 대신 장면별, 첫 영상 성탄 찬송 재사용) + 효과음 16개.
  재료와 배치는 `silence400/sound/`(place.json = 해설 시각, cues.json = 음악·효과음, takes.json = ElevenLabs 출처), 섞기는 `node motion/films/sound.mjs silence400 v`.
  - 해설판에서 음악을 통째로 줄이지 않는다(첫 영상 해설판의 아쉬움): 목소리 음역대(1.2–4.5 kHz)만 목소리에 맞춰 최대 ~6 dB 비켜 주고, 나머지는 ~2 dB.
    곡마다 음량을 맞춰 말하는 동안 목소리가 음악보다 6–7 LU 크게. 전율 순간(제목, 빛이 달려갈 때, '오늘', 부활의 빛)에는 목소리를 비우고 음악이 터진다.
  - 생성된 음악은 요청한 시점에 정확히 터지지 않는다 → `sound.mjs --envelope`으로 실제로 커지는 지점을 재서 그림의 순간에 맞춰 배치(필요하면 한 곡을 잘라 이어 붙임).
  - 사운드판(해설 없음)도 같은 재료로 함께 만든다.
