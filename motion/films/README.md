## 1. 무엇을 위해 만드나

- **주 대상: 성경을 잘 모르는 크리스천.** 목표는 성경 내용을 전하고, 성경과 가까워지게 하고, **직접 성경을 펴서 읽게** 하는 것이다(2026-10-30 결정).
  - 비신자 반응은 참고하되 **우선순위는 맨 뒤**다. 여호와·인자 같은 성경 용어는 바깥 사람에게 맞춰 순화하지 않는다.
  - 성경 속 위치를 보여 준다(책·장, 구약→신약 연결). 끝 화면은 **읽기 안내**(영상에 나온 장)로 끝낸다.
- **우리의 역할은 성경 내용 전달이다 — 설교가 아니다(2026-10-31 관리자 결정).** 우리는 목회자·신학자가 아니다. 성경이 워낙 방대해서
  성경을 안 읽던 사람에게는 성경 내용 자체가 몰랐던 사실이다 — 그러니 **성경에 무엇이 쓰여 있고, 언제·어디서·어떤 배경에서 일어났는지**를
  「침묵의 400년」처럼 정확하고 감동 있게 보여 주면 된다(주제를 일부러 '숨은 사실'로 고를 필요는 없다).
  - 화면의 중심은 본문(개역개정 원문 인용과 장절), 연대·지도·역사 배경(성경 밖 기록·고고학 포함, 출처 확인).
  - 해석이 필요한 곳은 "전통적인 해석입니다"처럼 해석임을 밝히고(예: 다니엘 2장의 네 나라), 해석이 크게 갈리는 내용은 다루지 않거나 "본문이 말하는 것"까지만.
  - 적용·권면은 끝에 짧게 한 줄 이하. "이 장을 직접 읽어 보세요"로 성경으로 보낸다.
  - **기준은 한국 개신교 대다수가 인정하는 것**: 사이트와 같은 복음주의·개혁주의 구속사 관점, 개역개정. 교단·학자마다 갈리는 것
    (종말의 시간표·천년왕국 견해, 창조 연대, 은사 논쟁 등)은 한쪽 편을 들지 않는다 — 다루지 않거나 모두가 동의하는 본문까지만.
    역사·고고학 사실도 주류 학계와 한국 교회가 받아들이는 것만, 출처를 확인해서.
- **감동과 전율, 영화 같은 느낌.** 정보를 많이 담는 것보다 **감정의 흐름 하나**가 중요하다. 연도·배경 역사는 설명란·고정 댓글·사이트로 넘긴다.
- **내용이 먼저다.** 3분 안에 넣으려고 서두르지 않는다. 담을 것이 많으면 줄이고, 남은 시간은 전율 장면과 숨 쉴 자리에 준다.

## 3. 원고와 글자

- **해설 원고 = 화면 글자.** 목소리로만 나오고 화면에 없는 문장은 만들지 않는다(소리를 못 듣는 사람, 무음 재생, 목소리 없는 언어판).
  - `script.json`: 줄마다 **id**(번역의 열쇠). `text` = 화면 글자, `voice` = 읽는 부분(반드시 `text` 안에 그대로 있어야 함), `voice: null` = 화면 전용.
  - `kind`: `narr`(해설) · `quote`(성경 원문) · `label`(화면 표기). `/` = 세로 화면 줄바꿈 자리.
  - 한국어 문장을 고쳐도 번역은 id로 이어진다(고친 줄은 번역을 다시 확인). 첫 영상은 한국어 문장 자체가 열쇠라 한 글자만 고쳐도 모든 언어에서 그 줄이 빠졌다.
- **성경 인용은 그 언어 공인 번역본 원문 그대로.** 한국어는 개역개정이다.
  - `node motion/films/check-quotes.mjs <폴더>`로 bskorea 원문과 글자 단위로 대조한다(WebFetch는 구절을 지어내므로 쓰지 않는다).
  - 장절 번호는 그 성경의 번호를 따른다(예: 독일어 말 4:6 = 3:24). 두 구절을 잇는 연출은 겹쳐 쓰기 대신 **위아래로 놓고 금빛 선으로 잇는다**(어느 언어 성경에서도 성립).
  - 외경(마카베오 등)은 성경으로 인용하지 않고, 역사 자료로 설명란에만 쓴다.
- **읽히는 글씨.**
  - 첫 영상과 같은 명조(Noto Serif KR 600)를 쓰되 크게 쓴다. 첫 영상 자막은 세로 72px, 이번 영상 초안은 42–54px라 폰에서 약했다.
  - 한 번에 한두 줄만 띄운다. 긴 구절은 조각마다 바꿔 띄우거나 핵심만 인용한다.
  - 읽는 시간은 **1.5초 + 글자당 0.12초** 이상을 준다. 글자는 그림 위에 얹지 않는다(어두운 띠·빈 자리).
- **유튜브**에는 화면 글자와 별도로 자막 파일(SRT)도 올린다(검색·자동 번역).

## 4. 다국어 — 영상 두 벌, 언어는 한 영상의 오디오·자막 트랙으로 (2026-11-01 관리자 결정)

새 영상은 **두 벌만** 만든다. 언어가 늘어도 영상은 늘지 않는다 — 그 언어의 해설·자막·제목을 영어판에 트랙으로 붙인다.

| | 한국어판 | 영어판(국제판) |
|---|---|---|
| 화면 글자 | 한국어(개역개정) | 영어(ESV) |
| 해설 | 한국어 | 영어(기본 트랙) + 반응이 확인된 언어들 — **같은 영상의 오디오 트랙** |
| 자막 | 한국어(위쪽) | 검수를 통과한 모든 언어(위쪽) |
| 제목·설명 | 한국어 | 언어별(유튜브 언어 탭) |
| 올리는 곳 | 한국어 채널(쇼츠·일반 영상), 인스타그램, 스레드 | **국제 채널**(세로 = 쇼츠, 가로 = 일반 영상) |

**왜** —
- 나라·언어마다 채널을 나누면 영상을 다시 올려야 한다(조회·댓글·구독이 0부터). 휴대폰 인증 한도로 채널을 계속 늘릴 수도 없다.
- 유튜브는 영상 하나에 언어별 오디오·자막·제목을 붙인다. 시청자 언어에 맞는 것이 자동으로 나오고, 시청 시간은 한 영상에 쌓인다.
  2026-11-01 한국어 채널 스튜디오 → 언어 → 언어 추가 창에서 확인: 일반 영상 = 썸네일·오디오·수동 자막, **쇼츠 = 오디오·수동 자막**(언어별 썸네일만 없음).
- 영어 글자판인 이유: 한국어 글자는 외국 시청자에게 낯설고, 쇼츠는 언어별 썸네일이 없어 첫 화면이 곧 화면 글자다. 라틴 문자는 스페인어·포르투갈어 시청자도 대충 읽는다.
- 영어판을 국제 채널에 두는 이유: 한국어 채널 조회의 86%가 홈 추천이고, 그 추천은 "한국 55세+ 크리스천" 신호로 돌아간다(1b).
  같은 내용의 영어판이 섞이면 신호가 흐려지고 두 영상이 조회를 나눠 먹는다. 국제 채널은 스페인어 쇼츠 반응이 있던 곳이고, 영어판 하나가 모든 언어를 담으니 채널은 두 개로 끝난다.

**번역은 전부 원스크롤바이블 과정으로.** 제목·설명·자막·해설 원고 모두 역번역 확인 + 원어민 검수를 통과한 것만, 성경은 그 언어 공인 번역본 원문 그대로(`fetch-verse`).
유튜브 자동 더빙·자동 번역, Meta AI 번역은 쓰지 않는다(유튜브 자동 더빙은 우리 채널 설정에 없다 — 2026-11-01 확인).

**플랫폼별 기능 (2026-11-01 직접 확인)**

| 플랫폼 | 다국어 해설 | 다국어 자막 | 그래서 |
|---|---|---|---|
| 유튜브 일반 영상·쇼츠 | ✅ 언어별 오디오 트랙(스튜디오에서 손으로, API 없음) | ✅ 수동 자막(API로) | 영어판에 트랙으로 |
| 인스타그램 릴스 | ❌ 직접 만든 더빙 업로드 없음(Meta AI 자동 번역만 — 쓰지 않음. 내 더빙 업로드는 페이스북 릴스 전용) | ❌ 자막 파일 업로드 없음 | 한국어판만 |
| 스레드 | ❌ | ❌ | 한국어판만 |

**만드는 방식**
- 영어판은 같은 코드에서 글자만 바꿔 렌더한다(세로+가로 약 10분). 영어판의 화면 글자 = 영어 원고(3절 규칙 그대로), 다른 언어는 자막이 그 역할을 한다.
- **시간표에 여유를 둔다.** 스페인어·포르투갈어 해설은 대개 영어보다 길다 — 언어마다 해설 줄이 영어판 장면 자리에 들어가는지 재고, 넘치면 원고를 줄이거나 말 속도를 조금(≤1.1배) 올린다.
- 언어 하나에 드는 일: 원고 번역(55줄 내외), 성경 원문 인용, 역번역·원어민 검수, 해설(ElevenLabs), 위쪽 자막(vtt), 제목·설명. 렌더는 없다.
- **자막은 검수를 통과한 모든 언어, 해설은 반응이 확인된 언어부터**(해설은 ElevenLabs 비용과 듣기 검수가 든다). 시작: 영어(기본) + 스페인어·포르투갈어(브라질).
- 올리기: 영상·제목·설명·자막 = 지금처럼(업로드는 스튜디오, 정보·자막은 API), 오디오 트랙 = 스튜디오 언어 탭에서 세로·가로 각각.
- 국제 채널 가로판은 노출을 크게 기대하지 않는다(새 채널의 긴 영상은 노출이 거의 없었다) — 트랙만 같이 붙이고, 승부는 쇼츠.

**순서와 도구** (「침묵의 400년」으로 처음 해 본 것, 2026-11-01 — 결과는 부록)
1. 영어판 렌더: `node motion/render.mjs v|h --page films/<이름>/film.html --lang en` → `motion/out/film-en-<v|h>.mp4`. 3초 간격 밀착 시트로 넘치는 글자를 본다
   (그림 코드에서 직접 그리는 글자는 폭에 맞춰 줄바꿈을 넣어야 한다 — 03줄이 화면 밖으로 나갔었다).
2. 해설 생성(ElevenLabs, 그 언어 원어민 다큐 목소리, 줄당 두 번): 읽을 말 = 그 언어 i18n의 그 줄(`…` 뒤만 읽는 줄은 한국어와 같게) —
   `node motion/films/voice-lines.mjs <이름> <lang>` → `sound/voice-lines-<lang>.json`(이 글을 그대로 보낸다).
   생성 호출이 돌려준 세션 id를 `{줄: [a, b]}`로 적어 두고, 상태 결과(파일로 저장됨)를 `node motion/films/fetch-takes.mjs <이름> <lang> <sessions.json> <상태 파일…>`.
3. 맞추기: `node motion/films/fit-voice.mjs <이름> <lang>` → `sound/place-<lang>.json`. 테이크 고르기 → 시작을 최대 1초 당기기(앞줄도 같이) →
   다음 줄을 최대 2초 늦추기 → 줄 안의 긴 쉼 줄이기 → 최대 1.12배. 무음 박자(`place.json` `quiet`)와 단어 맞춤(`sync_start`, 예: 'Today' = 143.1초)은 지킨다.
4. 섞기: `node motion/films/sound.mjs <이름> v|h --lang <lang>` → 영어는 해설 입힌 mp4, 다른 언어는 오디오 트랙 mp3 + `sound/<lang>.vtt`(위쪽 자막).
5. 들은 대로 읽었나: 목소리만 받아쓰기(ElevenLabs Scribe) → `node motion/films/check-voice.mjs <이름> <lang> <받아쓰기 결과>` — 다른 단어만 나온다(숫자 표기 차이는 무시).
6. 제목·설명: `youtube-intl.json` — 검수된 문장(T1, 해설 줄, 끝 화면, 화면 표기)만으로 짜고, 새 문장은 원어민 검수(`motion/reviews/film-<이름>-yt.md`).
   썸네일: `py motion/films/<이름>/thumbs/make.py --lang <lang>`.
7. 올리기(국제 채널, 비공개): `node motion/films/intl.mjs entry <이름> v|h` → 스튜디오 `__osbUpload('en', { entry })` →
   `YT_AS=GLOBAL node motion/films/intl.mjs api <이름> v|h <id>`(언어별 제목·설명, 자막, 표준 라이선스) → 스튜디오 언어 탭에서 오디오 트랙·언어별 썸네일(`../README.md` 10단계)
   → 자동 자막 지우기(`yt-api.mjs asr-off`, `../README.md` 11단계).
8. **한국어판에도 같은 외국어 자막**(관리자 결정 2026-11-01): `node motion/films/captions-on-ko.mjs <이름> en es pt-BR` → 같은 번역문을 한국어 해설 시각에 맞춘
   `sound/<lang>.ko-timing.vtt`(국제판 자막은 그 언어 해설 시각이라 한국어판과 최대 2초 어긋남) → 올리기는 9단계와 같이 스튜디오로
   (API `yt-api.mjs caption-file <id> <파일> <lang>`은 한 개 400점 — 한두 개, 또는 고친 파일 교체 `--replace`에만).
9. **자막 언어는 고정 목록 27개**(관리자 결정 2026-11-01, 해설은 그대로): en es pt-BR de fr it pl ru tr zh-Hans zh-Hant ja ar fa hi bn ta id vi th tl sw
   uz ne km mn my (+ ko). 근거 — 채널 대상(성경을 잘 모르는 기독교인)·유튜브 시장·실제 조회 국가(ANALYTICS.md 11/1): 이탈리아·폴란드는 가톨릭 다수·고령층,
   튀르키예는 큰 유튜브 시장, 우즈베크·네팔·크메르·몽골·미얀마는 **한국에 사는 이주민**(체류외국인 278만, 2025 법무부 — 한국 교회 이주민 사역,
   한국어판 영상을 외국인 동료에게 보여 줄 때). 바꾸려면 관리자 결정. 번역 `i18n/CAPTIONS-BRIEF.md`(언어 2개씩 에이전트) → 검수
   `i18n/CAPTIONS-REVIEW.md`(언어마다 별도 에이전트, 보고만, HIGH/MED 남으면 안 올림 — **HIGH/MED를 고친 언어는 고친 줄만 새 검수
   에이전트로 다시 확인**하고 올림(관리자 결정 2026-11-01); LOW 반영·원문 그대로인 구절 조정은 재검수 없이) → 자막 파일 `captions-on-ko.mjs <이름> <lang…> [--timing en]`
   (국제판 = 영어 해설 시각) → **올리기 전에 만든 .vtt를 언어마다 눈으로 확인**(검수는 json을 보므로 자막에 실제로 뜨는 모양 —
   특히 1번 줄 — 은 따로 본다; 11/1 fa·tr이 동사 하나로 시작해 다시 올림) → 올리기는 **스튜디오 화면으로** `motion/youtube/studio-caption.js` `__osbCaptions([[lang, 파일], …])`
   — API 자막은 한 개 400점이라 16개 언어 × 영상 4편이면 며칠 걸리지만, 스튜디오는 할당량이 없다(한 언어 약 15초).

**기존 영상** — 첫 영상(14분·21장면)은 언어마다 따로 그린 판이라 합칠 수 없다. 더 투자하지 않고, 이미 예약된 외국어 쇼츠는 그대로 둔다.
다만 화면 글자 자막(`motion/subs/<lang>/film-h.srt`, 19개 언어)은 모든 언어가 한국어와 시각이 같아서, **한국어 음악판(66VfBSXxAs8)에 그대로 올렸다**
(2026-11-01, 스튜디오 — 영어는 자동 자막 때문에 API로). 해설판(wrEYqvOU1O8)·해설 쇼츠는 해설이 한국어뿐이라 화면 글자 자막만으로는 맞지 않아 넣지 않는다.

**사이트** — 번역·검수를 통과한 언어를 브라우저가 그 자리에서 그린다(파일·업로드 없음). 사람을 모으는 곳이 아니라 들어온 사람이 둘러보는 곳이다.

- **판단은 유튜브 스튜디오 숫자로.** 해설 언어를 늘리거나 줄이는 기준: 쇼츠 "계속 시청함" 비율, 평균 시청 비율, 조회·구독, 오디오 트랙별 시청. 정기 분석([ANALYTICS.md](ANALYTICS.md))에서 정한다.
- 번역은 **한국어 원고를 확정한 뒤** 시작한다(영어 원고 → 다른 언어도 한국어 원고의 id를 따른다).

## 6. 사이트 /film 개편 (영상을 올릴 때 함께 — 2026-10-30 승인)

1. **/film/ = 영상 모음.** 맨 위에 최근 영상을 크게, 아래에 모든 영상 카드(포스터·제목·길이·가로/세로·볼 수 있는 언어).
2. **영상마다 자기 주소.** 예: `/film/story/`(14분 전체 이야기), `/film/silence/`(침묵의 400년). 공유·검색 노출·VideoObject를 영상별로.
3. **기존 링크는 그대로.** 이미 퍼진 `/film/?lang=..#cross` 같은 주소(유튜브 설명란·인스타)는 `/film/story/`의 같은 장면으로 자동 연결.

5. 메인의 "14분 영상으로 보기" → "영상으로 보기".
6. GA 이벤트에 `film`(어느 영상인지)을 붙여 영상별로 비교.

main 배포는 관리자 허락을 받고 한다.

- 새 영상 올리기: `py motion/films/publish.py <폴더> <slug>`(film.html·스크립트·script.json·글꼴 부분집합·film.m4a → `film/<slug>/f/`),
  `film/<slug>/index.html`(silence를 본떠 `FILM` 설정·챕터·읽을 말씀), 포스터, `films.json` 한 줄. sitemap·llms.txt는 `films.json`에서 자동.
- GA: 모든 재생 이벤트에 `film` 파라미터(맞춤 측정기준 등록 필요 — `tools/ANALYTICS-SETUP.md`).

## 7. 만드는 방식 (코드)

- **모든 영상은 영화처럼 만든다 — 그림책 그림·포스터·도표·게임 만화 느낌은 쓰지 않는다**(관리자 2026-11-02: 첫 영상을 함께 분석한 뒤
  "이 채널에서 만드는 영상은 전부 지금 방향으로"). 첫 영상(「한눈에 보는 성경 이야기」)이 품질 기준이다:
  1. **공간과 움직이는 카메라** — 카메라가 공간 속을 날고 걸어 들어간다(구름을 뚫고 에덴, 갈라진 바닷길, 해 질 녘 성벽, 밤의 지구).
  2. **빛이 주인공** — 노을·안개·등불·금빛 한 줄. 빛은 나오는 자리가 있고 번진다(렌즈처럼: 번짐, 빛줄기). 평평한 흰 번쩍임 금지.
  3. **넓은 세상 속 작은 사람** — 크기의 차이가 경외감을 만든다. 인물은 작게, 그늘 속에, 얼굴을 크게 그리지 않는다.
  4. **절제** — 차분하고 어두운 색, 빈 공간, 영화 자막 같은 작은 명조체, 필름 입자와 가장자리 어둠. 숫자 계기판·이름표 지도·번호 목록 금지.
  5. **영화를 참고한다** — 화풍은 영화(OPUSCAR의 영화 룩, 특히 깊이와 빛이 있는 것)와 회화에서 찾고, 재료 질감(먹·유화·목판)도 빛과 깊이로 쓴다.
  화풍 후보는 세로 스틸 한 장을 폰 크기로 보고 "영화 같은가, 1초에 무엇인지 읽히는가" 둘 다로 거른다. 실크스크린 포스터와 word-log 동굴
  만화는 「메시아」 시안에서 "일러스트 느낌이라 가벼워 보인다"로 빠졌다(밝고 평평한 그래픽·캐릭터 키트는 이 채널 영상에 쓰지 않는다).

- **세로가 메인이다**(관리자 2026-11-02: "숏츠 즉 세로가 메인이고 가로는 TV를 위한 것 — 파일럿 만들 때도"). 구도·글자·움직임은 세로
  (1080×1920)로 먼저 짜고, 가로는 그 장면을 TV에 맞게 옮긴다. 파일럿 시안·영상도 세로를 먼저(초안 페이지 맨 앞), 가로는 확인용.
- **화풍은 폰에서 내용이 읽혀야 한다**(같은 날: 로마 모자이크 시안 — "글씨도 안 보이고 내용 전달도 잘 안 되는 풍"). 질감이 화면
  전체를 덮는 화풍(모자이크·점묘 등)은 지도·글자·인물이 묻힌다 — 큰 형태, 높은 대비, 큰 글자가 먼저. 고를 때 세로 스틸 한 장을
  폰 크기로 보고 "이 장면이 무엇을 말하는지" 1초에 읽히는지 본다. 그래서 3부는 실크스크린 여행 포스터(큰 지명·거리 계기)로 바꿨다.
- motion-skills **word-log 키트**(flatnight·cavesil·fogforest… `kits/templates.jpg`)는 세로 구도와 인물 동작(걷기·무릎 꿇기, BODY-CHECK
  통과)의 참고로만 본다 — 그 그림체(만화 캐릭터·평면 일러스트)는 위 '영화처럼' 기준에 맞지 않는다(cavesil 동굴 시안이 빠짐).

- **두 말씀을 잇는 장면은 `lib-link.js`로**(관리자 2026-11-03: "말씀 연결 시 위아래 선으로 하던 장면 연결이 어색해 — 지난번에도 그랬는데").
  두 구절을 위아래에 놓고 선으로 긋지 않는다(도표처럼 보이고, 폰에서 두 덩어리를 동시에 읽어야 한다). 한 번에 한 구절을 읽게 하고,
  잇는 것은 빛이 한다: `Film.link(ctx, t, 'A', 'B', a, b, { style })` — `carry`(같은 자리, 빛이 건너감) · `depth`(옛 말씀이 멀어지고 새 말씀이
  다가옴) · `horizon`(금빛 지평선을 따라 카메라가 옆으로) · `ember`(같은 말이 불씨가 되어 날아가 새 말이 됨). 이어지는 말은 각 줄의
  `script.json` `hl`. 시안 비교는 `?link=<style>&lab=1`. 관리자가 고른 것을 기본으로 삼고, 새 방식은 이 키트에 더한다.
- **땅(3D 지형)은 격자를 세상에 고정**하고(카메라를 따라 격자가 움직이면 카메라가 움직일 때 땅이 자글거린다), 칸마다 앞뒤로 부드럽게
  음영을 넣는다(칸마다 한 색이면 벽돌처럼 보인다). 「메시아」 `terrain()`이 그 방식이다(2026-11-03).
- 한 파일짜리 캔버스 영상: `motion/films/<이름>/film.html` + `script.json` + 장면별 그림 모듈. 공용은 `../pilot/lib.js`, `lib-film.js`.
- **화풍은 motion-skills에서 고른다**(관리자 결정 2026-10-31). 로컬 사본은 `C:\Project\motion-skills`(github.com/jungrok5/motion-skills)이고, 목록은 `canvas-film/references/STYLE-INDEX.md`입니다.
  **지금은 재활용보다 발굴이 먼저다**(관리자 2026-11-02: "매번 같은 화풍만 쓰면 질릴 수 있으니 재활용을 우선하지 말고 아직은 스타일 발굴을 더"):
  부마다 그 뜻을 재료 자체가 해내는 화풍을 STYLE-INDEX 전체(우리 21 · 키트 29 · Lemo-Opuscar 66 · OPUSCAR 98)와 Lemo-Opuscar 저장소에서 찾고,
  앞 영상에서 쓴 화풍은 꼭 맞을 때만 쓴다. 초안 페이지에는 그 화풍의 실제 참고 장면을 보여 준다(`review.json` `samples.ref` — 저장소의
  `styles/<slug>/poster.jpg`, `styleboard/img/opuscar98/<번호>.jpg`; 원작 마스코트는 `crop`으로 뺀다). 목록이 충분히 커지면 골라 쓰는 쪽으로 바꾼다.
  찾을 곳은 다음과 같다(순서가 아니라 범위).
  1. 키트(`canvas-film/kits/`, 29개, 표는 `kits/README.md`): 이 영상에서 나온 `lamplit` 등잔 아래 두루마리, `inkmap` 잉크 지도, `illuminated` 채색 필사본. 여기에 word-log에서 온 `glass` 스테인드글라스, `papercut` 종이 오림, `ukiyoe`, `storybook`, `charcoal`, `hopper` 등.
  2. 첫 영상의 21개 화풍(종이 오림, 스테인드글라스, 금빛 선 …).
  3. 맞는 것이 없으면 OPUSCAR 98개 영화 룩이나 그 바탕 레포 Lemo-Opuscar(기법 66개)에서 골라 우리 것으로 다시 그린다. 기법만 빌리고 장면·인물·음악은 베끼지 않는다.

  장면 목록을 보여 줄 때 화풍마다 출처(키트/첫 영상/Opuscar 번호)를 함께 적는다. 영상이 끝나면 새로 만든 룩을 motion-skills의 키트로 다시 넣는다. 방법은 `kits/README.md` → Adding a kit입니다. 함수를 그대로 옮기고, 영상은 별칭으로 바꾸고, 전후 스틸이 픽셀 단위로 같은지 확인한다.

  키트는 영상 폴더에 `kit-<이름>.js`로 복사해(vendored) 쓴다. 그래야 키트를 고쳐도 끝난 영상은 바뀌지 않는다. 「침묵의 400년」이 이 방식의 첫 예다: `kit-lamplit.js`·`kit-inkmap.js`·`kit-illuminated.js`에, 영상만의 인물은 `illum-figures.js`에 두었다.

## 8. 검토 순서

1. **시나리오·원고를 먼저 제안하고 컨펌**받은 뒤 그린다. 큰 연출 변경도 계획 → 컨펌 → 작업.
   **보이기 전에 아래 2·3(관점 검수·시청자 리뷰)을 먼저 돌려 반영한다** — 리뷰 에이전트는 부마다 감동·전율 점수(0–5)와 넘기고 싶은 순간을
   보고하고, 에이전트가 반영한 뒤 초안 페이지를 만든다(2026-11-02~). 1번 대상(성경 잘 모르는 크리스천)의 점수가 낮은 부는 고친 뒤 다시 리뷰.
   - **초안 페이지(2026-11-02~)**: `node motion/films/review-page.mjs <이름>` → `motion/out/review/<이름>.html`을 아티팩트로 올린다
     (처음엔 새로 올리고 주소를 `review.json` `artifact_url`에, 다음부터는 그 주소에 다시 — 새 세션은 먼저 읽기). 관리자가 아내와 함께 본다.
   - **페이지는 초안만**(관리자, 2026-11-02 "검토용 페이지일 필요 없고 초안만"). 의견 칸·고르기 버튼·점검표는 넣지 않는다 — 의견은 대화로 받는다.
   - **한눈에 들어오게**(관리자, 같은 날 "쭉 읽으면서 검토하기 쉽지 않고 한눈에 안 들어옴"): ① 맨 위 한 줄 요약(`review.json` `logline`) +
     **한 화면 그림판** — 부마다 화풍 그림 한 장(앞 영상에서 같은 화풍으로 그린 실제 장면, `parts[].samples`) · 이름 · 느낌 한 낱말(`feel`) ·
     핵심 한 줄(`key` = 줄 id) ② **들리는 대로** — 목소리로 읽는 말만 이어서, 부마다 '화면' 한 문장(`story`) ③ 정할 것 ④ **자세히**(화면 글자·그림
     설명·메모·줄 id)는 접어 둔다. 줄마다 카드를 늘어놓는 원고표는 맨 위에 두지 않는다.
   - 점검(성경 인용 원문 대조, 목소리 분량으로 길이 추정, 읽는 시간이 빠듯한 줄, 메시지 점검 12문항)은 에이전트가 하고, 걸린 것만 대화에서 짧게 알린다.
   - 의견을 반영하면 `review.json`의 `round`를 올리고 `rounds`에 요약과 바뀐 줄 id(`changed` — 페이지에 금빛 표시), `feedback_log`에 받은 의견과 처리를 남긴 뒤 같은 주소에 다시 올린다.
     720p 시안·밀착 시트(4단계)도 같은 주소에 붙인다(한 영상 = 한 주소).
2. **관점 검수**(복음주의·개혁주의 구속사, 개역개정): 지적은 반영한다.
3. **시청자 리뷰**(성경 잘 모르는 크리스천 · 성경 잘 아는 신자 · 비신자): 고치지 않고 결과만 모아 보고, 관리자가 고를 것을 정한다. 1번 대상의 의견이 우선.
4. 관리자와 아내분이 720p 시안으로 본다. 가능하면 성경을 잘 모르는 가족에게도 보여 준다(목소리가 들어간 뒤).

## 9. 첫 영상과 「침묵의 400년」에서 배운 것

- **새로 넣은 것이 많을수록 급해지고 품질이 떨어졌다.** 장면을 더하기보다 덜고, 남은 장면을 공들인다.
- **전율 장면은 시간이 필요하다.** 글을 다 읽기 전에 밑줄이 지나가면 전율이 없다. 소리가 없어도 시각만으로 고급스러워야 한다.
- **왜 전율인지 화면이 말해 줘야 한다.** 성경을 모르면 "같은 말이 이어진다"의 의미를 모른다. 사람(세례 요한), 물건(손대지 아니한 돌)은 **이름과 뜻**을 화면에 준다.
- 낯선 상징(신상)은 무엇이고 어디서 읽는지 먼저 알린다("다니엘 2장 · 느부갓네살 왕의 꿈").
- 지도에 시대가 안 맞는 지명을 두지 않는다(페르시아 시대의 알렉산드리아).
- HUD(이름표·작은 그림·연도·메달)가 한꺼번에 많으면 산만하다. 이야기에 필요한 것만.
- 무언가 "하얀 언덕"처럼 정체를 알 수 없는 그림은 빼거나 바꾼다. 효과가 겹치거나(입자와 다음 장면) 깜빡이면 싸 보인다.
- 글씨 대비: 금빛 글씨가 양피지 위에서 빛나면 묻힌다 — 잉크는 진하게, 빛은 글자 뒤에.

## 9b. 올리기 전 점검표 — 첫 영상에서 얻은 최적화 (자세한 방법은 [../README.md](../README.md))

## 10. 계속 만든다 — 다음 주제는 분석으로 고른다 (2026-10-31 관리자 결정)

"계속 만들지"는 고민하지 않는다. **성경의 내용으로 영상을 계속 만든다** — 많은 사람이 성경을 알고, 궁금해하고, 찾아보고, 직접 읽고 싶게.
숫자는 "만들지 말지"가 아니라 **무엇을, 어떻게 만들지**를 정하는 데 쓴다.

- 정기 분석(월·목, [ANALYTICS.md](ANALYTICS.md))이 매번 **다음 추천 제작 주제 2~3개**를 근거와 함께 올린다. 근거:
  - 우리 영상 반응 — 어떤 쇼츠·장면이 계속 시청되고 공유·저장되는지(예: 「광야」 쇼츠가 한국어 975회·평균 111.6%, 스페인어 1,121회로 가장 높음.
    인스타그램은 다르다 — 릴스 「사사 시대」 997회, 같은 유튜브 쇼츠는 115회)
  - 시청자가 들어온 길 — 유튜브 검색어("성경이야기", "성경다큐"), 스튜디오 '트렌드'의 검색 주제("성경 재미있게 읽기", "성경 읽기 요약"),
    우리 영상이 추천된 옆 영상(하박국 설교, 계시록 강해, 크로스뷰, 대체신학·아달랴 등 성경 역사 영상)
  - 시기 — 교회력·절기(성탄, 고난주간·부활절, 추수감사)와 사회적 관심사(그 주에 사람들이 성경과 관련해 검색하는 것)
  - 국제 채널은 언어별 반응
- **우리가 가장 좋아하는 이야기의 결(관리자, 2026-10-31)**: 성경을 읽어야만 보이는 **하나님의 연결 — 계획과 사랑**.
  예) 룻기: 모압 과부 룻이 보아스를 만나 → 오벳 → 이새 → 다윗 → 마태복음 1장 예수님의 족보(마 1:5). 읽는 것 자체로 "이게 이렇게 이어져 있었구나"를
  알게 되는 이야기. 「침묵의 400년」의 말라기 → 누가복음, 이사야 61장 → 나사렛 회당도 같은 결이다. 주제를 고를 때 이 연결이 뚜렷한지를 먼저 본다.
- **지금 추천(2026-11-02 분석 — 근거는 [ANALYTICS.md](ANALYTICS.md))**: ① 메시아 예언과 성탄(창 3:15 → 미 5:2 → 눅 2, 대림절 11/29 시작 — 11/23 전후 공개)
  ② 룻기(보리 추수 → 마 1:5, 추수감사주일) ③ 광야 40년 — 만나(출 16 · 신 8:2–4 → 요 6:35, 「광야」 쇼츠가 두 언어 최고).
- 주제 후보 목록(쌓아 가며 고친다 — 「침묵의 400년」처럼 성경의 한 흐름을 따라가는 이야기):
  룻기 — 이방 여인에서 다윗과 예수님의 족보로 · 요셉 — "너희는 나를 해하려 하였으나 하나님은 그것을 선으로 바꾸사"(창 50:20) ·
  모리아 산 — 이삭(창 22) → 솔로몬 성전(대하 3:1) · 유월절 어린 양 → "하나님의 어린 양"(요 1:29) · 에스더 — 하나님의 이름이 한 번도 안 나오는 책의 섭리 ·
  마태복음 1장 족보의 네 여인(다말·라합·룻·우리아의 아내) ·
  메시아 예언과 성탄(창 3:15 → 베들레헴) · 광야 40년 · 바벨론 포로 70년(다니엘·에스겔·에스더) · 사도행전 이후(복음이 로마까지) ·
  계시록 한눈에(해석이 갈리는 부분은 편들지 않음 — 1절) · 성경은 어떻게 우리 손에 왔나(사본·번역).
- 고른 주제는 1~3절 기준(주 대상, 형식, 원고·글자)과 8절 검토 순서를 그대로 따른다. 관점은 사이트와 같다(복음주의·개혁주의 구속사, 개역개정).
- 볼 숫자(형식을 다듬는 데): 평균 시청 비율, 쇼츠 계속 시청 비율, 공유·저장, utm 링크 유입, 사이트 기도문 완독(`prayer_complete`).
