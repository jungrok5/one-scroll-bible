# 이상 확인 — {film} (렌더마다, 시험본·시안을 보내기 전에)
기계 검사(frame-qa: 검은 화면·얼어붙음·튐·깜빡임, look-check: 밝기)는 기술 고장만 잡는다. 이 단계는 **눈으로 보아 이상한 것**을 찾는다
(관리자 2026-11-10: "프레임으로 보면 이상한데 … 만든 영상을 확인해서 이상유무 판단하는 스텝이 제작공정에 있어?" → "ㅇㅇ").
점수는 매기지 않는다(점수 리뷰는 관리자가 요청할 때만 — 2026-11-05). 보고만 한다.

1. 시트 만들기: `py motion/films/frame-sheets.py {film}` (가로 `--ori h`, 시험본·부분 렌더는 `--video <mp4>`) → `motion/out/frames/{film}/sheet-*.jpg`(0.5초마다, 시각 표시).
2. 확인 에이전트 하나(하위 에이전트, 지시문 = 아래 '확인 지시문' 그대로)에게 시트 폴더와 원고(script.json — 줄마다 at·screen)를 넘긴다. 같은 세션의 본 작업자가 직접 봐도 되지만, 그린 사람이 아닌 눈이 낫다.
3. 답을 `review.json` `anomaly_check`에 그대로: `{ render: <manifest render>, at, sheets: "<폴더>", issues: [{ t, what, severity: "MAJOR|MINOR", status: "open" }] }`.
   **고치기 전에 관리자 확인**(2026-11-10 "에이전트 리뷰받아서 피드백받아서 수정할 땐 확인받고 수정해"): 반영할 것 · 반영 안 할 것을 정리해 보이고, 확인받은 것만 고친다.
   고친 것은 `status: "fixed"`(어떻게를 `fix`에), 고치지 않기로 한 것은 `status: "ok"` + `why`. 그림을 고치면 다시 렌더 → 시트 → 확인(렌더 지문이 바뀌면 검사가 다시 요구한다).
4. 관리자·가족이 본 이상한 프레임은 `film.mjs feedback`으로 남기고 같은 목록에도 넣는다(다음 확인에서 같은 종류를 먼저 본다).

## 확인 지시문 (하위 에이전트에게 그대로)
너는 영상 「{film}」의 프레임 시트를 보고 **눈으로 보아 이상한 것만** 찾아 보고한다(파일을 고치지 않는다). 시트: `motion/out/frames/{film}/`(manifest.json에 시트마다 시각 범위). 원고: `motion/films/{film}/script.json`(줄마다 at = 시작 초, screen = 그 줄 동안 보여야 할 것).
시트를 한 장도 빼지 말고 모두 Read로 본다. 찾을 것:
- 몸: 손가락 수·관절 방향이 틀린 손, 목각·마네킹 같은 손, 덩어리 같은 몸, 막대 같은 팔, 얼굴이 뭉개져 섬뜩함, 자세가 불가능함(references: C:\Project\motion-skills\canvas-film\references\BODY-CHECK.md)
- 물체: 공중에 떠 있음, 땅·탁자에 안 닿음, 잘림·튀어나옴, 크기가 앞뒤 장면과 안 맞음, 겹쳐 뚫고 지나감, 같은 물체가 두 번
- 글자: 자막·인용이 얼굴·주인공·밝은 면 위에 얹혀 안 읽힘, 글자끼리 겹침, 화면 밖으로 넘침, 그림 안에 글자처럼 보이는 무늬
- 화면: 장면이 바뀔 때 이상한 섞임(반쯤 남은 물체), 갑자기 다른 색·밝기, 빈 화면처럼 보이는 구간, 일러스트·포스터·만화처럼 보이는 컷(채널 기준은 '영화처럼'), screen 문장과 전혀 다른 그림
- 성경과 어긋남: 원고 screen에 적힌 시간대·장소·옷과 다른 것(예: 밤이어야 할 곳이 낮)
답: JSON 하나 — `{ "issues": [{ "t": <초>, "what": "<무엇이 이상한지 한 줄>", "severity": "MAJOR|MINOR" }], "clean_ranges": "<문제없던 구간 요약>" }`. MAJOR = 시청자가 바로 알아챌 것. 없으면 issues: []. 한국어로.
